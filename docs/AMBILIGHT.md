# SunnyTV 0.2.9 灯带试用版

在“设置 → 灯带设置”启用并授权蓝牙，连接 SP658E。播放自己的视频时，从 Media3 的 SurfaceView 取样四边颜色，通过电视蓝牙直接控制灯带。无手机依赖，无录屏授权。退出播放、切后台或暂停超过约 700ms 后发送固定色；灯带自行保持颜色。

## 使用

- 固定色色板支持遥控器：左右改变色相，上下改变饱和度，确认保存，返回取消。移动时实时预览，亮度单独调整。也可选预设或输入 RRGGBB。
- 默认带入本次实际定位：96 个控制单元，零基地址左上49、右上18、右下3、左下65，顺时针地址递减。蓝色两端已各加回一个单元；上、右、下、左长度为31、15、34、16。
- 重新定位按“末端 → 左上 → 右上 → 右下 → 左下”。左右移动1，上下移动10；确认继续，返回上一角；全部合法才覆盖原定位。一单元可能对应一组实际灯珠。
- 四边测试显示上红、右绿、下蓝、左黄；选择角后可微调地址。恢复固定色结束测试，离开设置也恢复。
- 默认目标10次/秒，可选5或15。只有一个 BLE 写入在途，只保留最新待发送颜色，不堆积视频帧。不做高延迟平滑。设置中的蓝牙提交耗时是 Android 接受写入的耗时，不等于灯珠实际发光延迟。

## 边界和协议

首版支持 SP658E / V4023.21 / SPI RGB。按设备名与厂商标识筛选，首次连接后在本地记住地址，不在代码中写入用户设备地址。其他固件在完成验证前拒绝控制。

状态查询、两片通知重组、FFE0/FFE1 服务、MTU185、XOR封装、0x52静态RGB、0x53模式和0x63七段自定义已由前期探针验证。七个长度/颜色槽限制了空间精度：首版每边一种颜色，不能宣称逐灯珠视频同步。相邻同色合并，单段不超过150，无法装入七槽的布局拒绝保存。

采样为160×90 RGB小图，取四边窄带，排除连续黑边；使用自己的视频层，避开播放菜单与字幕叠层。每次只有一次 PixelCopy 在途；采样和颜色计算在工作线程，蓝牙使用另一工作线程。Activity停止后废弃晚到帧。缩放裁切按可见Surface区域取色。取色失败保持重试并恢复固定色。

HDMI 和其他应用的全局画面不在本版范围；此前本电视HDMI取屏为黑色。HDR、受保护视频以及具体机型PixelCopy行为必须实机验证，不把独立探针的MediaProjection成功等同于此集成路径已验证。崩溃、强制停止或蓝牙断电时无法保证送达恢复指令。

## 验证与交付

新增纯 Kotlin 测试覆盖官方静态报文、已保存的蓝色端点、七槽限制、600个单点位置、通知分片及超时、四边取色和黑边排除。Android测试使用生成的四色SDR视频验证真实Media3第一帧与SurfaceView PixelCopy，并验证色板遥控器确认及设置入口。

候选工作流只上传测试构件，不发布GitHub正式版、不改latest。使用既有仓库签名Secret，验证与0.2.8相同的公开证书、包名、61/0.2.9及非debuggable属性。四ABI音频库保持源码构建。

当前实现已进入编译/自动测试；最终通过项、安装包哈希及电视验证结果在交付后追加。端到端实际灯光延迟尚未测定，不能保证目标刷新率等于实测刷新率。
