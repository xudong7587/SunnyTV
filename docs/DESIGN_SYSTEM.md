# SunnyTV 视觉系统与页面规范

## 核心风格

私人影院、安静、通透、有层次。整套应用使用相同背景、文字、焦点和间距规则；电影的色彩从 Emby 背景图自然进入画面，不靠按钮大面积换色。最早截图只约束单媒体库的沉浸区，其他页面在其基础上原创延展。

视觉原型：`preview/index.html`。原截图：`docs/reference/user-lumiplayer-reference.jpg`。原型示例数据不进入 Android APK。

## 颜色与排版

| token | 当前值 | 用途 |
|---|---|---|
| Background | #090D0D | 页面底色 |
| Surface | #17201C | 面板、抽屉、卡片底 |
| SurfaceRaised | #222D26 | 聚焦底、较高层次 |
| Accent | #D6E6A5 | 主按钮、焦点、进度 |
| Text | #F3F5EF | 标题与主要内容 |
| Secondary | #ABB7AD | 简介、元数据 |
| Border | #344138 | 弱边界 |

Native 来源是 `feature/ui/Theme.kt`，新增页面先用已有 token，不直接各自定义新的主题色。默认系统字体，无外部分发字体文件。中文不要用特别细的字重；大标题 38–44sp，页面标题 26–32sp，分区标题 19sp，主要卡片标题 14–16sp，元数据 11–13sp。这是当前代码起点，远距离可读性以电视实测调整。

页面两侧安全留白约 40dp，顶部导航约 72dp，底部24–40dp；组件间距主要为8、12、16、24、32dp。主按钮40–48dp以上高度，面板圆角12–18dp，媒体卡片12dp；减少过大圆角的“手机卡片感”。

## 组件统一

**媒体库卡片**：统一16:9容器，Primary原图优先，默认Fit；标题在下方。图片自带“电影/电视剧”文字时不再在图片上盖同一标题。当前库无图才用文字卡片。

**竖海报卡片**：2:3；评分与已看状态低占比覆盖；片名与年份位于图下。焦点不得把周围海报压成不可辨认细条。

**继续观看卡片**：16:9横图，底部真实进度。季集显示 `Sx · Ex`；剩余时间无有效时长时不能捏造。多来源同名条目保留来源信息作为后续可见消歧。

**透明Logo**：可用时使用Emby Logo；加载失败使用标题文本，不让默认背景图顶替片名。Logo过宽时Fit，不拉伸。

**背景**：Backdrop铺满裁切，左侧深遮罩、底部渐变。无背景时使用统一渐变。没有自动预告、循环视差、实时模糊或同屏第二个播放引擎。

**设置行**：左主说明与次说明，右当前值。聚焦覆盖整行，切换只改变该设置；尚无实现的能力只作为说明，不显示假开关。

## 页级约束

总首页上方推荐不要过高，应在首屏让用户看到“我的媒体库”和继续观看的开头。下面纵向扩展NextUp与来源分组的最新入库。单库首页上方则可以用更强的电影氛围与左右分区，下面仍需有正常可浏览内容。

海报墙要优先看全海报，而非给每张卡片加繁重底座。详情页和播放器控制使用同一文字层次，但播放器应更简洁，暂停或操作时才突出按钮。

设置页不使用电影标题作为背景干扰阅读：仅保留低对比环境色。来源页和文件浏览不硬造缺少的影视简介。

## 动画与焦点

聚焦边框即时可见，缩放初值1.025、130ms；减少动画模式关闭缩放。背景更新采用240ms停留去抖；后续淡入目标约150–220ms，但要测图片解码与层合成，不为动画反复解析播放直链。

返回必须恢复页面滚动和合理焦点。面板打开后不可导航到被遮挡的底层控件。控件需要稳定ID，列表使用含sourceId的稳定key；不要把网络内容变化和自动焦点放在无限重组循环里。

## 原型与原生实现差异

HTML使用1920×1080视觉稿比例，原生采用系统dp；不是将像素直接除以一个常数。原型包括效果更完整的顶部胶囊、主海报呈现和部分未实现筛选；原生首轮已有页面，但这些细节需继续对齐。原型中演示的按钮不作为Android功能完成证据。

## 设计验收

在目标电视用正常观看距离检查：封面图内文字不裁切，选中与聚焦区分明确，简介不压住操作，长片名不越界，没有海报时也能导航，页面转换不突然换主题，连续按键不出现多个焦点或隐形焦点。
