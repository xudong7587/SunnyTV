# SunnyTV 开发规划与实施说明

**版本**：0.1.0-dev1 开发快照  
**更新**：2026-09-17  
**交付目的**：先完成整体设计与核心源码，随后由用户在 PC 端通过 Codex 继续编译、联调和迭代。本文取代此前 MediaIndex TV 暂名任务书。

## 0. 阅读本方案前

本项目正式命名 **SunnyTV**，独立于 MediaIndex、Moonfin 和 LumiPlayer。视觉依据为本对话最早的用户截图；本轮没有取得可核对的视频完整画面，因而没有声称提取了 B 站或抖音里的设置页和播放器页面。其余页面是同一视觉语言下的原创延展。

源码已包含主要页面及真实服务请求，不是只有接口名的演示壳；但没有进行 Android 整包编译及真机播放测试。102 项纯 Kotlin 测试与浏览器原型测试只证明对应范围，不证明 APK 已可安装或更流畅。不能按文件数或代码行数换算功能完成百分比。

## 1. 产品目标与优先级

SunnyTV 是一个专注电视的私人媒体客户端：用户已有 Emby 负责媒体组织和刮削；CloudDrive2 是独立文件来源；MediaIndex 负责既有 STRM 与网盘播放解析。播放器把内容统一呈现，并尽量缩短从选片到首帧的链路。

优先级：P0 可构建、真实播放、鉴权安全、进度正确；P1 一致的全套 TV 界面与无障碍遥控操作；P2 基于真机数据的起播与滚动优化；P3 扩展格式、来源与高级播放器功能。不能为了精美动画牺牲基本播放，也不能为了少写页面将整个首页简化成文件列表。

首版不承担下载器、网盘整理、资源搜索站、直播平台、手机遥控服务或跨平台阅读器功能。不接管 MediaIndex 的转存、命名、删除、签名或数据库逻辑。

## 4. 统一视觉系统

采用深墨绿黑背景、低饱和暖绿灰面板、柔和浅黄绿焦点，氛围主要来自 Emby 的电影背景，不为每一页设置不同的高饱和主题色。具体值与排版见 `DESIGN_SYSTEM.md`。

正常、聚焦、选中和禁用是不同状态。聚焦使用 2dp 边框与轻量缩放；选中状态采用弱填充，不应与焦点混淆。阴影只作层级，不叠加光晕、持续发光、粒子或实时毛玻璃。

屏幕按 16:9 规划；使用 dp/sp 与系统密度，不硬编码物理 4K 宽度。底层视频 Surface 与界面分辨率分开。不能靠调 `wm size` 证明客户端优化。

## 5. Emby 图片与元数据复用

| 区域 | 优先资源 | 缺失处理 |
|---|---|---|
| 媒体库卡片 | 该库 Primary → Thumb → Backdrop | 统一风格的文字默认卡片 |
| 电影竖海报 | Primary | 有可用图片时降级，否则标题占位 |
| 继续观看 / 单集 | Thumb → Backdrop → Primary | 标题、集数和进度仍可用 |
| 页面背景 | 当前影片 Backdrop / 父级背景 | 静态深色渐变，不强制拉伸竖海报 |
| 片名图形 | 透明 Logo | 清晰的系统字体标题 |

原生媒体库图包含文字时，不额外往图片里重绘一个标题；库名可置于图片下方供聚焦与无障碍读取。默认采用 Fit 保留图内文字，容器空白由同色背景处理。

缓存键包含 `sourceId + imageItemId + type + tag + size`；多服务器相同 ItemId 不共用图片。图片加载使用按来源授权的 HTTP 客户端，不把 Token 放入图片 URL。默认不在电视请求 TMDB 重新匹配影片。

当前图片缓存为共享内存预算和 200MiB 磁盘上限，避免每加一个来源就复制一份缓存预算；仍需依据实际电视测量，暂不宣称符合所有低内存设备。

## 6. TV 焦点与状态规则

方向键只在当前可见、可交互区域移动。顶部导航、海报行、详情操作、抽屉、弹窗都要有明确入口和出口。长按不能无限堆积动画或触发同一播放的多次请求。

确认键：海报进入详情；明确的播放按钮进入播放器。返回键：先关闭轨道面板/弹窗，再关闭 OSD，再离开页面。不能每次关闭字幕选择都重建播放器。

现有代码有按页面保存的焦点标识、Lazy 列表状态保存以及请求取消。Codex 需继续补显式跨区域焦点关系、非可见卡片恢复、弹窗与播放器底层的焦点隔离、进程死亡后的导航恢复。当前实现不等于已通过 200 次连续遥控按键测试。

## 7. 架构与源码边界

```text
app/src/main/java/io/github/xudong7587/sunnytv/
├─ MainActivity.kt / SunnyApp.kt
├─ core/model                 来源、图片、条目、播放请求与基础运算
├─ core/network               可取消 HTTP、有界重定向、鉴权作用域
├─ core/storage               配置、Keystore 凭据、文件续播位置
├─ core/playback              播放事件队列和异步回报
├─ source/emby                用户登录、库/条目/图片/API 播放
├─ source/clouddrive          WebDAV 协议与无 Android 依赖的 XML 解析
├─ source/strm                小文本解析、递归限制、共享 URL 解析器
└─ feature
   ├─ AppModel.kt             页面协调、异步任务、取消与状态
   ├─ ui                     统一组件及浏览/设置页面
   └─ player                 Media3 原生视频与控制层
```

初期使用一个 Gradle app 模块和包级边界，避免过度拆成很多空模块。接入层不引用 Compose；UI 不拼接服务器 API；播放网络与图片网络共用安全策略。公共模型改动必须回归 Emby、CD2、STRM 三条链路。

当前 AppModel 内存缓存未提供全量分页驱逐/持久化索引，浏览大量目录后的内存上限是明确后续任务。不要通过删除页面功能解决长期内存问题。

## 8. Emby 接入契约

使用普通用户登录，不要求管理员 API Key。服务根地址需要明确填写 API 可达根，例如 `http://NAS:8096/emby/`，或保留真实反代前缀；不盲目裁掉路径。URL 中查询参数的顺序和编码不用于手工签名改写。

源码已经调用的能力：

- `Users/AuthenticateByName`：换取用户 Token，密码不持久保存。
- `Users/{UserId}/Views`：媒体库，包含原生图片标识。
- `Users/{UserId}/Items/Resume`、`Items/Latest`、`Shows/NextUp`：首页行。
- `Users/{UserId}/Items` 与单条详情：查询、分页、收藏过滤基础能力。
- `Shows/{SeriesId}/Seasons` / `Episodes`：季集。
- `Items/{ItemId}/Images/{Type}`：图像及 tag/尺寸参数。
- `Items/{ItemId}/PlaybackInfo`：媒体源与播放会话。
- `Sessions/Playing`、`Playing/Progress`、`Playing/Stopped`：有序回报。

最新入库有些接口返回数组，不可统一当成 `Items` 包装对象。跨库或来源的同名作品不自动合并，主键必须包含来源。

**当前播放协商仍是基础版**：请求直放/直流、不自动转码，尚未提交从目标设备实际能力生成的完整 DeviceProfile。服务端明确不提供可用直放媒体时给出提示，不谎称硬件支持所有编解码器。需在下一阶段实现能力画像、媒体源选择及正确转码回退，且保持用户可见。

Emby 返回需要专用打开/关闭的直播或临时源时，当前明确不支持。普通远端媒体要求额外 Provider 请求头时，不把网盘凭据搬到电视，而优先走服务器返回的流路径；该回退需实际服务器验收。

对于带前缀的反代：相对 URL 继承前缀，根相对 URL 尊重服务器给出的根路径。后者可能需要修正反代配置或明确的路径映射，禁止全局字符串替换和静默猜测。

## 9. CloudDrive2 接入契约

**当前只有已写入代码的 WebDAV 兼容模式，不是已完成 CD2 原生 gRPC。** 用户填写 CD2 实际开启的 WebDAV 服务地址，而非管理网页端口。HTTP 207 是正常的多状态目录响应，不能当成连接失败。

目录采用 `PROPFIND Depth: 1`，请求和解析在后台执行；仅展示文件夹、视频、STRM。服务器密码通过 Keystore 本地加密。播放独立文件时保存以来源与路径摘要标识的本地进度，不冒充已同步 Emby。

XML 解析限制 UTF-8、8MiB、10,000 个响应条目；禁用外部实体和 DTD，过滤超出配置根路径的 href，合并成功 propstat，避免误用 404 属性组。

后续原生 gRPC 需依据实际 Core 版本和 proto 生成客户端，先做能力探测再增加实现，不虚构 RPC。WebDAV 是独立可维护的 fallback，不因原生 API 加入而删除。

本轮没有 NFO/同目录图片的自动刮削，也不在启动时扫描全部网盘。优先保证浏览和播放，再按用户实际文件结构增量读取辅助文件。

## 10. MediaIndex STRM / 302 / 代理流

本次根据既有任务书及实际读取到的 MediaIndex 播放代码，适配入口：

```text
{base_url}/api/play/{token}
```

典型链路是 `Emby 元数据 → 可达媒体入口 → MediaIndex → 302 或服务端代理 → Media3`。CD2 是另一条独立文件来源，不强迫 Emby 已经可用的 STRM 再绕 CD2/FUSE。

现有策略：64KiB STRM 上限；UTF-8 BOM、CRLF/LF、空白和注释兼容；唯一 HTTP(S) URL；3 层显式 STRM 递归限制与循环检查；没有后缀的 `/api/play/{token}` 不当作文本读取、不默认当成 HLS。

重定向独立限制 8 次；同一会话使用统一 UA；Range 原样交给网络层/Media3；跨域移除 Emby/CD2 认证头；HTTPS→HTTP 降级默认拒绝；不缓存 MediaIndex 返回的 `no-store` 临时 Location。

现有播放入口重试为一次用户明确触发的重试，不叠加无限播放器/Provider 重试。若 STRM 文件里本身保存的是过期临时 URL，重新读取 STRM 并重新做 PlaybackInfo 的完整恢复策略仍待实现；不要把当前重试按钮描述为通用自动刷新。

429、401/403、409、416、302 循环与断流要分别测试。409 可能是 MediaIndex 资产/令牌失效，不能统一解释为解码器错误。跨域测试目前有源码，必须在可下载 OkHttp/MockWebServer 的环境执行后才算通过。

## 11. 播放控制与会话

初版使用官方 Media3 / ExoPlayer 与 PlayerView 的默认 SurfaceView，不复制整套 Moonfin Flutter 框架。未集成第二引擎，未移植 Moonfin 的 DV/音频补丁。

已有：播放/暂停、快进后退、继续位置、音轨选择、外挂文本字幕配置、字幕关闭、适应/裁切/填充、停止释放、首帧渲染回调和基本错误提示。会话回报采用串行 actor 和最多三个事件槽，合并心跳但保留开始/停止；网络回报不阻塞 UI。

尚需：音视频能力检测、用户转码选项、自动下一集/跨季、字幕延迟/默认轨道、解码错误分类、播放列表、刷新率/HDR/直通矩阵和 Android MediaSession。不要把设置中的说明文字当成功能开关。

当前首帧指标从 PlayerActivity 创建引擎计时，不含上一页的 PlaybackInfo/STRM 解析。完成端到端计时前，不用该值与 Moonfin 点击播放总耗时比较。
