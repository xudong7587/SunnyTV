# 1.0.6 /79 视频取色性能修复

基线GitHub main `eb42049` /1.0.5，工作分支 `codex/tv-playback-stutter`。用户授权使用ADB诊断电视并降低灯带取色成本，后续明确增加玻璃聚焦使用系统/主题色。

## 实机证据

电视TCL MT5879，Android11/API30，32位应用。最初安装1.0.4 /77。用户将《凡人修仙传》卡顿集置于播放，UI标题“慕兰之战21”，原画AVC 3840×2160 /约25fps，使用OMX.MS.AVC.Decoder。

- 同步开启时多次读回955–984ms，硬件日志视频输入约25/s、渲染输出一度3–4/s，大量drop frame，并有500–800ms主线程慢分发及内存回收。
- 临时在应用设置中关闭画面同步、从同一继续播放入口恢复。在22秒对照的稳定播放段，输出连续约25/s，无主线程慢分发。启动恢复位置时的drop frame不计为稳态，不能声称整段零丢帧。
- 已在设置中恢复画面同步开启。用户自行覆盖安装1.0.5 /78后重新采样，完整缓冲读回仍为602–1021ms，约每6秒一次；非读取段输出约25–26/s，读取附近仍有丢帧。由此不能把卡顿简单归咎于硬件解码器性能，也不能宣称1.0.5完全解决。
- 现场日志、版本和UI开关确认在忽略目录 `.local-tests/playback-stutter/`。日志不进入仓库，不记录公开媒体URL或凭据。

## 实现

- 每次只向32×18网格读取一次，RGBA输出576像素/2304字节；原160×90为14400像素/57600字节，输出数据与像素处理量降低96%，不等于底层读回耗时降低96%。仍从完整解码缓冲缩小，避免错误地截取左上角。
- 四边的采样点按各自边缘区域求平均，沿现有灯带四边分段均匀着色，保留三帧过滤和时间平滑、灯珠定位及SP658E七段约束。
- 所有读回按实际耗时限制为约10%时间预算；用户刷新率作为上限。一次请求在途时不轮询，没有重复在途请求或持续空转。
- 单次读回>=250ms时暂停当前视频同步，保持当前灯色并在设置显示原因；不关闭持久配置。新播放重建采样器或用户重新开关同步可以重试。首次探测本身仍可能造成一次停顿，不能保证硬件层零开销。
- 黑边扫描也受慢读回保护；若视频层过慢，停止额外扫描并保留当前画面比例/已识别范围。这可能保留无法低成本探测的编码黑边。
- 液态玻璃聚焦沿用当前palette.accent（含系统Monet/主题强调色），未聚焦文字保留深浅模式黑白。仅修改颜色和输入框聚焦描边/光标，不改玻璃采样、折射、透明度或手机材质。

Android的PixelCopy仍需从Surface取得硬件缓冲，再缩放至目标位图；多个单点请求仍可能重复触发等待。小网格不能承诺免除厂商驱动的整帧访问/等待，因此耗时保护仍有必要。参考 [PixelCopy官方接口](https://developer.android.com/reference/android/view/PixelCopy) 和 [Android11 Readback实现](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android11-release/libs/hwui/Readback.cpp)。
