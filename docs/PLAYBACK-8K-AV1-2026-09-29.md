### NAS 短时硬件转码实验

- NAS CPU 实报 Intel Core 3 304；Emby 容器已映射 `/dev/dri/renderD128`。
- 容器自带 FFmpeg 包含 AV1 解码器和 Intel 驱动。单纯列出解码器不作为转码成功证据。
- 首次独立运行缺少驱动搜索路径，VAAPI 初始化失败。按容器自带驱动位置，为测试进程指定 `LIBVA_DRIVERS_PATH=/app/emby/lib/dri`、`LIBVA_DRIVER_NAME=iHD` 后成功；未修改服务环境。
- 实验链路：原 STRM → AV1 VAAPI 硬解 → `scale_vaapi` 缩至 3840×2160 → H.264 VAAPI 编码，目标 15 Mbps → null 输出。
- 150 帧成功，退出码 0；FFmpeg 编码阶段约 3.80 秒，输出媒体时间约 4.97 秒，末尾报告约 39 fps / 1.31x；包括解析及启动的总墙钟时间约 5.74 秒。
- 实验关闭音频和字幕，输出直接丢弃，不生成视频文件。
- 只证明该样本开头短片段的硬件视频转码可行；不证明全片、并发、音频转码、HLS、拖动或电视播放已经通过。

## 当前判断

最可疑的是电视对该 8K AV1 码流的解码能力或驱动兼容，而非冷门文件导致 MediaIndex 无法取到原文件。当前 NAS 取流正常；昨天 PlaybackInfo 确有一次 12.4 秒延迟，这不能直接解释持续不起播。

不能仅凭 MT9653、GPU 名称或 4K 屏幕推断精确的 AV1 解码上限；需要电视能力表、解码器日志，或同一文件经兼容转码后的对照播放。手机能播也不证明电视能解同一码流。

SunnyTV dev29 公开源码仍发送 `EnableTranscoding=false`。现有服务端兜底为直流，不会自动把 8K 转成 4K；播放器缓冲或超时参数无法替代降分辨率转码。

## 两种解决路径（设计建议，尚未实现）

### 后续方向确认与授权限制

用户随后明确继续使用 Emby，并提出播放器默认原片走302、手动选择分辨率时走 Emby 转码。优先采用路径 A，无需因此先开发 MediaIndex 转码模块。

Emby 免费服务器提供基础软件转码；硬件加速转码属于 Premiere 功能，正式接入前需要核对服务器授权与用户转码权限。依据：[官方功能矩阵](https://support.emby.media/support/articles/Premiere-Feature-Matrix.html)、[Premiere 官方介绍](https://docs.emby.media/premiere.html)。本次直接运行 FFmpeg 的成功结果只验证硬件/驱动能力，不能证明免费 Emby 会通过播放 API 启用 GPU。

建议交互为“原片（默认）/ 4K / 1080p / 720p”，转码档位同时规定分辨率上限、目标码率及兼容编码。清晰度切换需要重新协商 PlaybackInfo、采用服务器返回的转码流、保留当前进度并释放旧会话；选转码时不能继续落回115原片302。还需确认现有 STRM/302 插件允许转码请求经过 Emby。

转码按需边拉取、边处理、边输出，不必预先下载全片。NAS承担源下载、视频处理和输出；家中观看的NAS到电视传输为局域网流量，远程观看才使用家庭公网上传带宽。当前未实现清晰度按钮或 Emby API 转码接入。

### A. 复用现有 Emby 转码

SunnyTV 增加设备能力协商与用户可选择的“服务器兼容播放”，让 Emby 返回 HLS 转码流。NAS 已有 FFmpeg 和 GPU，可先避免在 MediaIndex 中另建会话管理。

仍需验证：Emby 用户转码权限、实际转码配置/授权、STRM 插件是否绕过转码、真实 PlaybackInfo 和 HLS 行为。上述命令行实验不代表 Emby API 转码链路已接通。

### B. MediaIndex 增加可选转码模块

适用于希望不依赖 Emby、让 SunnyTV 直接使用 MediaIndex 的场景：

```text
支持原片：APK → 原有播放入口 → 302 → 115 原文件
需要转码：APK → 转码会话 → NAS 拉取115 → GPU解码/缩放/编码 → HLS → APK
```

- 保留既有 STRM 与签名、默认 302 行为；新增显式协商/转码会话入口，不通过修改已签名 URL 参数强行切换，也不按 UA 猜硬件。
- APK 提供实际解码能力及质量选择；媒体参数已知且设备明确不支持时提示兼容播放，允许用户手选 4K/1080p。
- 115 取流与凭据始终留在服务器；源 URL 不写日志，遵循原凭据作用域、TLS、跳转限制和链接刷新规则。
- 初版建议单路、按需 HLS，4K 或 1080p H.264；音频按客户端能力复制或转 AAC。不要先生产整部 36 GB 文件。
- HLS 分片与清单都鉴权，使用独立会话令牌、闲置过期、取消/退出释放、限定缓存和并发。清理只针对服务自有临时分片，不触及网盘原文件。
- 必须处理 seek 重启、片段时间戳、续播、转码失败、源链路刷新和硬件繁忙；不能只是包一条后台 FFmpeg 命令。
- NAS 需要同时承担115下载与向电视发送转码流；外网观看还受NAS上传带宽影响。
- GPU中的媒体引擎是当前已实测可用资源；现阶段无需依赖 NPU。超分、AI画质属于另外的功能范围。
