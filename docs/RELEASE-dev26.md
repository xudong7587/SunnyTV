播放首帧超时的一条修复，并让"超时"这类报错第一次能指明是哪一跳出的问题。

本版针对用户实机反馈：一条由 MP（MoviePilot）生成的 STRM 直接播放时报
「读取媒体超时，请检查电视到 Emby 的连接 · 错误码 2001 · 首帧前读取 · video/mp4」。
反编译 Media3 的数据源实现后确认，这条链（`HttpDataSourceException → IOException → ExecutionException → SocketTimeoutException`）
意味着**响应头还没到就超时**：错误码被判成 2001 而不是 2002，只是因为超时异常被 Media3 自己的异步包装挡住了分类，
不代表"不是超时"。当时的预算全项目共用 8 秒连接 / 25 秒读取，且首帧失败没有任何自动重试。

- 播放传输单独放宽首次响应预算：连接 8 → 15 秒、读取 25 → 60 秒。API、图片与 STRM 文本仍是 8 / 25 秒。
  跳转上限 8 次、跨域剥离 Emby / CD2 认证头、禁止 HTTPS 降级、统一 UA 与有界 TLS 校验全部逐条不变。
- 首帧前遇到瞬时传输失败（连接失败、连接或读取超时）会自动重试**一次**，界面提示「网络读取超时，正在自动重试一次…」；
  DNS 解析失败、TLS 失败、HTTP 4xx / 404、字节位置越界与解析错误不重试。失败后仍保留手动「重试此播放入口一次」。
- 超时提示改为给出实际主机与阶段，例如
  `请求主机 cdn.test:5244（直连媒体源，不是 Emby）· 阶段 等待响应（连接或首字节）· 已自动重试 1 次`。
  只打印主机与端口，不含路径、查询或签名；原来那句「请检查电视到 Emby 的连接」已删除，因为失败同样可能出在电视直连的 CDN 上。
- 顺带修掉两处误导性文案：HTTP 409 不再指向 MediaIndex，设置页直接播放测试不再写「MediaIndex /api/play 入口」。
  SunnyTV 与 MediaIndex 没有代码耦合，STRM 一律按"文件内唯一一条 HTTP(S) 地址"处理。
