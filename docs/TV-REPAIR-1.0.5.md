# 1.0.5 /78 电视修复候选（未发布）

基线 GitHub main `8893c09`，本地分支 `codex/tv-1.0.5-fixes`。本次于2026-10-23通过ADB连接用户电视；现装1.0.4 /77，Android11/API30，TCL MT5879，32位应用ABI。没有覆盖现有安装或用户配置。

## 实机证据与范围

- 用户确认静态冷白降低到24%后不闪。高白色RGB负载是重要因素，但没有电流/电压测量，不能判定电源、线材或控制器中的具体故障。
- 旧版日志含300–850ms主线程阻塞、GC阻塞；播放期间有约330ms耗时和连续38–41帧丢帧。系统历史gfxinfo累计卡顿帧73.43%，不是本轮新代码的性能数据。
- SurfaceFlinger显示3840×2160解码缓冲配1920×1080视图。旧PixelCopy使用holder.surfaceFrame充当缓冲坐标，存在取样不完整问题。
- 用户反馈裁切和拉伸均拉长、有些视频不响应；3840×1600/60fps杜比视界视频在裁切时，SurfaceFlinger已提交等比中心裁切（sourceCrop约497.8..3342.2），但实体画面仍被报告拉伸。怀疑厂商硬件视频层未按窗口裁切显示，尚需候选包实测。
- 杜比视界使用OMX.MS.DOLBY_VISION.DVHE.STN.Decoder，截图只有OSD、视频全黑。白色取样偏蓝仍需候选包读回日志核对，不能声称已修复杜比视界颜色。

## 候选改动

- 所有灯带静态/视频输出共用保守RGB总通道负载限制，相当于整条全白24%的实测稳定范围；按灯珠分段数量加权，统一缩放RGB保留色相。保留用户亮度设置；这是经验限载而非硬件电流保护。重复更新不重选静态灯效。
- PixelCopy读取完整解码缓冲，再在160×90复用数组映射可见区域；TV解码器裁切也换算到实际可见源区域。
- 灯带与黑边识别只允许一次视频读回在途。昂贵读回按耗时退避；黑边确认后停止探测，没有识别到黑边最多采样12次。保留有限重连和生命周期行为。
- 仅TV的ZOOM使用MediaCodec SCALE_TO_FIT_WITH_CROPPING，FILL使用SCALE_TO_FIT。手机画面模式维持现有实现；编码黑边按全帧识别。
- 仅API30–32且UI_MODE_TYPE_TELEVISION的玻璃改用实时GraphicsLayer及轻量边缘放大，避免背景位图读回、CPU模糊和上传。此兼容效果不等同AGSL模糊。手机LegacyGlass.kt和API33+shader保持不变。新增只移动子图层、不重绘父层的滚动回归。
