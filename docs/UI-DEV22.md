# SunnyTV dev22 · 改动与验证记录

基线：dev21 源码快照。目标：手机横屏浏览、媒体库推荐栏、轮播刷新、播放进度、字体与字幕外观、
长按菜单、设置顺序、品牌视觉、手机安全区与遥控/触摸导航。

## 1. 手机横屏下滑无法拉起「我的媒体库」

原因是设备判定只看宽度：`screenWidthDp<600` 才走手机路径，横屏手机宽度普遍 ≥600dp，于是被
当成电视，套用了「Hero 与内容两个全屏层 + GPU 平移」的电视转场。该转场由方向键驱动，手指
上下滑动不触发，所以滑不动。

新增 `LocalHandset`（`uiMode != television` 且 `smallestScreenWidthDp < 600`，与方向无关）。
首页在「手机或窄屏」时统一使用单个 LazyColumn（Hero 作为第 0 项），触摸滚动天然可到达媒体库；
电视仍保留原有的双层 Hero 转场。布局宽度相关的 `LocalCompact` 保持原义，未混用。

## 2. 媒体库推荐栏改造

- 新增 `LibraryHero`，排版逻辑与首页 Hero 完全一致：窄屏（竖屏手机）为「按钮在上、媒体块在下」，
  宽屏为「按钮在左、媒体块在右、整体下对齐」，媒体块占 58% 宽度；左侧仍保留原「播放 / 查看详情」
  按钮与标题信息。竖屏时媒体块与下方工具栏之间留出 26dp + 列表间距的呼吸区。
- 推荐内容默认随机：`AppModel.loadRecommendations` 通过现有 Emby 适配器以 `SortBy=Random`
  取 10 条，按库缓存；未加载完成时回退到已加载海报页的前 10 条，不会出现空白推荐栏。
- 背景更完整：媒体库页与首页 Hero 的渐变后移，顶部只留 6%～12% 的淡淡压暗。详情页改成与媒体库页
  相同的**固定全屏背景**（`Backdrop(item)`，图片完整铺满、不随内容滚动），只在屏幕下方保留渐变，
  标题与简介浮在背景之上；头图不再是一块 320dp 高、下面接平色的图块。

## 3. 刷新轮播图与相关媒体

- 首页：焦点在顶部时继续按「上」刷新（电视），手机滑到顶后继续下拉同样触发。
- 媒体库页：Hero 上按「上」，或海报墙顶部继续下拉，刷新推荐栏与该库第一页。
- 刷新期间显示与播放器完全相同的品牌 logo + `LOADING` 动画（`SunnyBrandLoading`，播放器已改为
  复用同一个 composable）。
- 电视端「按上」的优先级保持不变：首页先到顶部导航，再按一次上才刷新；媒体库没有顶部导航，
  在 Hero 上按上即刷新。首页原来不生效的原因有两个：一是顶部导航是页面内容的兄弟节点，
  按键处理挂在页面容器上导致导航获得焦点后收不到按键（已把处理移到根节点）；二是轮播在保持
  焦点时不会替换新的随机样本（已用 `heroRevision` 让手动刷新的结果立即生效）。

## 4. 播放页进度快速调整

- 已播放位置圆点常显；聚焦或拖动时放大并加描边环。
- 电视：在底部控制排按「上」聚焦进度条（`focusProperties { up = progressFocus }`）；单击左右为原
  10 秒步进，长按左右进入连续快进/快退，速度按 1.4 倍逐级加速并在进度条上方显示
  `目标时间 / 总时长`，松手才真正 seek。
- 手机：水平滑动不再限制在中三分之一，除屏幕左右各 24dp 的返回手势边缘外全屏可滑动快进；
  竖直滑动仍按左右半屏区分亮度与音量；双击分区（后退/播放暂停/前进）保持不变。
- 手机可直接按住进度条或圆点左右拖动到目标位置，松手生效。

## 5. 字体与字幕外观

- 原「字体」设置分类并入「外观」，分类列表简化为：主题 / 外观 / 首页 / 性能 / 媒体来源 /
  播放 / 设备与诊断 / 关于。「媒体来源」按用户要求在「性能」下方。
- 界面字体与字幕字体都可选「系统默认」或「用户自定义上传」；开发期间的私有构建曾临时内置过第三方字体，
  这些字体及其说明已全部移除（见 dev25 的公开版清理），仓库内不含任何字体文件，
  `scripts/check-project.py` 会直接拒绝 `app/src/main` 下出现 `.ttf/.otf/.ttc`。
- 新增「字幕外观」卡片：**顶部是实时预览**（`SubtitleStylePreview`，直接用播放器同一套
  Media3 `SubtitleView` + 同一个样式函数渲染示例字幕，不再是盲调），下面依次是字体、大小、
  描边（无/描边/投影）、位置（5 档）、背景（无/半透明黑/主题色半透明）五个变量。字体颜色取主题
  前景色，描边颜色取主题强调色，不单独存颜色，跟随主题切换。播放器通过 Media3
  `CaptionStyleCompat` 应用，并关闭内嵌样式与内嵌字号，保证设置真实生效。
- dev21 只保存自定义字体文件，升级后会自动把它继续当作已选字体（迁移逻辑在 `ConfigStore`）。

## 6. 长按菜单

- `FocusTile` 支持长按：遥控器按住确定键（repeatCount>0）或手机触摸长按。
- 菜单内容按条目类型给出：媒体库/文件夹/剧集 → 刷新媒体库、刷新元数据；具体影片/单集 →
  刷新元数据、删除。演员等条目不提供菜单。
- 删除需要二次确认，确认框明确说明「是否同时删除服务器文件由服务端与账号权限决定，无法撤销」。
  应用本身仍然只发 Emby 服务端请求，不做任何本地文件删除。
- 打开菜单后的 260ms 内忽略确认键，避免长按松手时的 KeyUp 误触发第一项。

## 7. 设置顺序

「媒体来源」移到「性能」下方；「字体」并入「外观」。分类标题仍沿用现有中文命名，未改名为「数据源」。

## 8. 品牌阴影

只作用在 logo 图形与 `SunnyTV` 文字本身：logo 使用与浅色聚焦媒体块相同的圆形柔和阴影，
文字使用原生文字阴影，不再给整个品牌区套一个圆角矩形外框阴影。

## 10. 菜单键与触摸方向键

- 遥控器「菜单」键直达设置页（`Key.Menu` 与 `KEYCODE_MENU` 双路径）；播放页是独立
  Activity，天然不受影响。
- 按验收结论**已移除**手机滑动模拟方向键的整块代码（`handsetSwipeNavigation`、
  `NavigationGesturePolicy` 及其契约测试）。手机端保留下拉到顶刷新轮播的手势。

## 验收第三轮修订（同日，按用户截图反馈）

1. **媒体库轮播与工具栏彻底分开**：`LibraryHero` 增加底部留白（宽屏 30dp、竖屏 56dp），叠加网格
   自身的 22dp 间距，细条媒体块不再压到「电视剧 · 全部内容 + 工具栏按钮」那一行；竖屏按用户要求
   把工具栏进一步推到下方（允许落到首屏之外），保证 banner 完整。
2. **顶部下移只在手机竖屏生效**：`handsetTopInset(cutoutTop, handset, portrait)`。之前用
   `smallestScreenWidthDp < 600` 判断手机，而 TV 预览的虚拟显示是 960×540dp，`smallestScreenWidthDp`
   只有 540，被误判成手机，所以电视端也跟着下移了。现在只有「手机 + 竖屏」才加 26dp，横屏与
   电视恢复原有高度。
3. **品牌 logo 去掉圆形阴影**：`softFocusShadow(CircleShape)` 会在 logo 外形成一圈柔光，看起来
   像圆形按钮，已移除；浅色模式的柔和阴影只保留在 `SunnyTV` 文字本身。
4. **媒体库轮播与首页对齐**：推荐取样由 10 条改为 7 条（1 个大块 + 6 个细条）；左键走完一轮后
   跳出循环并把焦点交回左侧第一个按钮（播放，或不可播放时的查看详情），与首页 `RotatingHeroCards`
   的 `onExitLeft` 行为一致。
5. **首页按上刷新修好**：原判定依赖 `moveFocus(Up)` 失败，但同一排按钮之间也可能被判定为"向上
   移动"从而吞掉按键。现在改为：焦点已在顶栏（`NavigationBridge.navActive`）时按上直接刷新轮播；
   焦点在内容区时按上先回到顶栏，再按一次刷新；没有顶栏的页面（媒体库等）按上即刷新。

## 验收第四轮修订（同日）

1. **媒体库工具栏到底重叠的根因**：`toolsOffset()` 在「工具行槽位尚未进入视口」时会把工具行放到**视口底边**，
   于是它正好压在 banner 上。现在改为固定停在 banner 底部 + 一个网格间距的位置（`heroBottom + itemGap`），
   首屏只会看到完整 banner，文字与那排按钮出现在下一屏。`LibraryHero` 同时改用 `heightIn(min=...)`
   并在 hero 项上 `clipToBounds()`，内容不会再越界画到工具行上。
2. **媒体库首页标题跟随滚动**：`LibrariesScreen` 把「所有媒体库」标题改成网格的第一项，滚动时与封面一起上移，
   不再固定占住顶部挡住卡片。
3. **顶部与 logo**：库页/详情页恢复顶部按钮与左上角 logo；顶部下移只在手机竖屏生效；logo 改用**系统原生
   elevation 阴影**（`Modifier.shadow`，由太阳圆盘投出），不再手绘圆环。
4. **字幕**：Media3 的描边宽度由框架写死、无法调细，按用户意见不改自绘渲染（不增加系统负担）；
   仅把「投影」的颜色改成**主题色的浅色**（`lighten(accent)`）以便阅读。
5. **详情页删除按钮**：读取 Emby 用户策略（`EnableContentDeletion` / `EnableContentDeletionFromFolders`），
   有权限时详情页出现「删除」按钮，走与长按菜单相同的二次确认流程；无权限则不显示。
6. **搜索页快速选择**：新增 `PinyinIndex`（使用系统 ICU `Han-Latin` 转写，不打包辞书、不额外下载），
   从用户已加载的媒体名里统计高频「首字/词」并配拼音首字母，供遥控器直接选择；键位是**纯文字**（无边框无底色，
   聚焦只变色），行尾是退格（⌫）与清除（✕）图标。

## 验收第五轮修订（同日）

1. **媒体库工具栏恢复"跟随滚动 + 到顶钉住"**：工具行仍由固定浮层绘制（网格里保留等高占位项），
   `toolsOffset()` 只在占位项进入视口时按它的真实位置跟随（`max(pinnedTop, slot.offset)`），滚到顶后
   钉在顶栏下方；当 banner 仍占满首屏、占位项还没出现时，工具行停在**首屏之外**（`viewportEnd +
   8dp`），因此不可能再压在 banner 或"向下查看更多媒体"文字上。焦点在工具行按「上」会回到 banner 轮播。
2. **搜索键盘改为标准遥控键盘**：A–Z 分三行、0–9 一行，全部是**纯文字键**（无边框无底色，聚焦只变色），
   行尾是退格（←）与清除（垃圾桶）图标。
3. **拼音匹配**：新增 `PinyinIndex.matches`，用系统 ICU 转写取每个字的拼音首字母并做**顺序包含**匹配，
   所以输入 `sdyq` 能命中「速度与激情」（首字母 sdyjq）；命中的条目直接以「拼音匹配」货架列出，
   可遥控器选中。整个匹配在本地完成，不增加服务端请求，也不打包辞书。

## 验收第六轮修订（同日）

1. **媒体库标题/工具行不再钉住**：按用户最终要求，这一行改成 banner 之后的**普通滚动项**（hero=0、工具行=1、
   海报从 2 开始，索引与焦点逻辑不变），跟随海报墙一起上下滚动，滚上去也不再固定到顶部，因此结构上
   不可能再压住 banner 或"向下查看更多媒体"文字。
2. **按文件夹入口对所有媒体库开放**：去掉原先"仅 `mixed`/`homevideos`/`tvshows`/`Folder` 才显示"的限制，
   电影等媒体库也能切到按文件夹浏览（`!episodeContainer` 即可）。

## 验收第七轮修订（次日，电视 + 平板实测）

1. **电视媒体库无法按下键进入下方内容**：工具行从浮层改成普通网格项后，Hero 的 Down 仍走"不滚动、直接请求焦点"，
   而工具行此时还没被 LazyGrid 组合出来，焦点请求失败。现在 `beforeMove(1)` 返回 false，让网格把第 1 项滚动进
   视口后再聚焦，各个媒体库都能从 banner 向下进入工具行与海报墙。
2. **媒体库任意位置按上都刷新**：删掉 Hero 自身的 Up 刷新分支，只保留根节点逻辑——先把焦点交回顶部导航，
   在导航上再按上才刷新。
3. **搜索键盘排布**：按电视输入法布局——左侧三行字母 A–Z，右侧两行数字 1–5 / 6–0 并在数字行尾放退格（←）
   与清除（垃圾桶）。
4. **左上角 logo**：取消太阳的阴影（圆盘阴影在任何情况下都像圆形按钮），只保留 `SunnyTV` 文字阴影。
5. **播放画面裁切**：裁切改为"等比例放大"——在 Media3 `RESIZE_MODE_ZOOM` 基础上再放大 12%，画面边缘延伸到
   屏幕外，同时把文件里烘焙的黑边一起裁掉；拉伸仍是 `RESIZE_MODE_FILL`。
6. **高码率 STRM 卡顿**：播放器缓冲从 15s/40s 提升到 **30s/120s**，目标缓冲按设备堆内存取 1/8（上限 160MB，
   下限 48MB），并把读取分配块从 64KB 提升到 **256KB**，让高码率直放有足够的预读余量。
7. **平板（2560×1200）首页滑动与横竖屏素材**：新增 `LocalTouchFirst`（按触摸屏能力判断），平板与手机一样走
   单列表可滚动结构；banner 的背景/海报改为按**屏幕方向**选择（竖屏用海报，横屏用 Backdrop），不再用逻辑宽度判断。
8. **随机算法**：首页轮播与各媒体库推荐都加入"新鲜度"优先——最近展示过的条目排到后面，未出现过的优先入选，
   并分别记住最近 240 / 120 条，避免总是那几张。
9. **手机/平板下拉刷新轮播**：下拉刷新对**所有触摸设备**启用（含平板）。除了列表的嵌套滚动，手势还**直接挂在
   banner 自身**（`pullDownOnBanner`）：在到顶状态下按住 banner 向下拖 72dp 后松手即刷新。
   第一次用 Compose 的 `detectVerticalDragGestures` 实现时，它在越过触摸阈值时会**无条件消费**拖动事件，
   于是 banner 上的向上滑动也被吃掉、页面滚不动。现已改为手写方向判定：只有「已经到顶 + 向下拖」才消费事件，
   一旦判定向上就把整个手势交还给列表，所以向上滑查看下面内容不再被阻断。
   真机验证：首页 banner 下拉后轮播确实换成了新的随机条目（界面树前后对比）。

## 验收第十轮修订（单一媒体来源）

**改动前**：多个 Emby 来源是**合并显示**的——首页的"我的媒体库 / 继续观看 / 最新入库 / 接着看"、
媒体库索引、搜索、轮播推荐都会把每个来源的内容混在一起。

**改动后**：同一时间**只显示一个 Emby 来源**，所有页面都只显示它的媒体：

- `AppModel.activeEmbySources()` 只返回一个来源：设置里选定的那个；没选过或所选来源已被移除时回退到第一个 Emby 来源。
- 首页 feed（媒体库、继续观看、最新入库、接着看）、媒体库索引、搜索（含服务端搜索与本地拼音匹配池）、
  轮播推荐取样、启动快照恢复、删除权限检查，全部只针对该来源；其余来源不再发起任何请求。
- **设置 → 媒体来源**新增「当前显示来源」一行，点开可切换要浏览的 Emby 来源（切换后立即重载该来源的首页与
  媒体库，轮播候选清空重取）；新添加的来源会自动成为当前来源；移除当前来源时自动回退到剩下的第一个。
- 海报缓存：键里仍然包含来源 id、媒体 id、图片 tag 与请求尺寸，所以同一来源内相同条目天然共用缓存；
  不同来源即使媒体同名也不会互相覆盖。

## 验收第十二轮修订

1. **首页"刷新了但看起来没变"**：首页轮播若设成"最新入库 / 继续观看"，刷新只是重新取同一份列表，
   所以视觉上没有变化（媒体库页用的是随机推荐，所以看起来正常）。现在手动刷新在非随机模式下也会
   **轮换候选池**（随机模式照旧重新取样），banner 一定会换。
2. **换一批按钮位置**：首页 banner 与媒体库 banner 都在"向下查看更多媒体 ↓"这行右侧放了一个
   **`换一批` 按钮**（圆形 repeat 图标，聚焦时显示文字），遥控器可直接按到，作为下拉手势的保底入口。
3. **媒体库 banner → 工具行的切换**：改为和首页"上/下区域切换"同一套做法——一次受控滚动把工具行
   **对齐到顶部内边距**（`revealItem(1, alignTop=true)`），再交接焦点，并带重复按键保护；
   不再出现先弹跳再卡住的情况。从海报墙往上回到工具行仍是"只移动焦点、不滚动"。

## 验收第十三轮修订

1. **撤掉 banner 里的按钮，恢复布局**：上一轮加在"向下查看更多媒体 ↓"右侧的「换一批」把 hero 文案列撑高，
   手机上媒体库 banner 的下沿被挤出屏幕、首页"继续播放"胶囊也被裁掉。现已删除这两处按钮，布局回到原样。
2. **刷新入口移到顶部钉住的那一行**：顶部导航在 首页 / 媒体库 / 搜索 / 设置 之后新增第 5 个圆形按钮
   （repeat 图标，聚焦时显示"换一批"），按下即刷新**当前页面**的 banner（首页或正在看的媒体库）。
3. **首页/媒体库"刷新了但没变化"的真正原因**：刷新确实执行了，但
   - 首页轮播若为"最新入库 / 继续观看"，重取的是同一份列表；
   - 媒体库 banner 用的是服务端随机取样，小库或库里条目少时每次会返回同一批（这也解释了为什么"第一个库能刷、
     第二个库刷不动"——差别只在于返回的样本是否碰巧变化）。
   现在手动刷新**保证换片**：首页在随机模式下重新取样、非随机模式下轮换候选池；媒体库 banner 在刷新完成后
   自动前进到列表中的下一张海报（并同步更新背景与标题）。

## 验收第十四轮修订（用户定位到根因）

用户实测发现：不同 Emby 来源提供的媒体库并不一致，而"首页 → 参与轮播的媒体库"列表把**所有来源**的媒体库
混在一起，勾选结果也跨来源保留。切到一个媒体库较少的来源后，勾选集合里没有任何属于该来源的库，于是
`loadHero` 取不到任何候选、首页轮播退回"最新入库"那份固定列表——刷新自然看不出变化（把该源设为"全部媒体库"
就恢复正常，与用户观察一致）。

修订：

1. **轮播媒体库列表跟随来源**：设置里的"参与轮播的媒体库"只列出**当前来源**的媒体库，不再出现其它来源的库。
2. **空选择自动回退**：当"使用全部媒体库"关闭、但当前来源一个都没有被勾选时，轮播改为按**该来源的全部媒体库**
   运行，并在设置里给出一行说明，避免轮播没有候选、刷新像是无效。
3. 结合上一轮的"手动刷新保证换片"，首页在任意来源、任意轮播模式下按顶部「换一批」或"到顶再按上"都应该
   能看到画面真的变化。

## 验收第十五轮修订

1. **按用户要求移除顶部「换一批」按钮**（"如无必要勿增实体"）：刷新入口只保留两种既有交互——遥控器在
   顶部导航上「按上」刷新当前页 banner，触摸设备在 banner 上「到顶继续下拉」刷新。上一轮的"保证换片"
   逻辑继续生效，所以看不到按钮也不会影响结果。
2. **媒体库 banner 向下被阻断**：banner 的"向下"其实有两条入口——外层 Box 的按键处理（已改走 `enterTools()`），
   以及轮播卡片自己的 `onExitDown`（仍在调用旧的 `gridFocus.move(1)`，而该路径已不再滚动、只请求尚未组合的
   工具行焦点，于是失败并表现为"按不下去"）。现已把两条入口统一到 `enterTools()`：一次受控滚动把工具行
   对齐到顶部内边距，再交接焦点。

## 验收第十六轮修订（用 TV 模拟器复现并定位）

用户反馈"电视按上/下被阻断"，我在本机启动 API 30 TV 模拟器，用
`TvInteractionTest#libraryHeaderCanMoveDownAndEscapeReturnsToParent`（聚焦轮播大块 → 按「下」→ 断言工具行排序按钮获得焦点）
稳定复现，并加临时日志定位到：**`enterTools()` 根本没被调用**。

原因：媒体库 banner 那个 Box 的修饰符顺序是 `gridFocusTarget(gridFocus,0,null,1).onPreviewKeyEvent{enterTools()}`。
Compose 的 `onPreviewKeyEvent` 按**由外到内**执行，`gridFocusTarget` 排在前面，它的「下」处理器先执行、调用
`navigator.move(1)` 并消费事件；而工具行已不再是常驻浮层、没被组合，注册表里没有 index 1 的目标，于是这次移动
静默失败、事件也被吃掉——表现就是"按下键被阻断"。之前能工作是因为工具行当时是常驻浮层，索引 1 的焦点目标始终存在。

修订：

1. 把 `onPreviewKeyEvent{enterTools()}` 移到 `gridFocusTarget` **之前**，保证它先接管「下」。
2. `enterTools()` 用两步确定性滚动（`animateScrollToItem(1)` 后再 `animateScrollBy(-pinnedTop)`）把工具行对齐到
   顶栏下方，然后请求**具体按钮**（排序按钮）的焦点，而不是给整行容器请求焦点。
3. 同步修正因"工具行不再钉住"而过期的测试断言（`Dev16PerformanceTest` 里对 `library:pinned-tools` 位置的检查）。

模拟器验证：`Dev16PerformanceTest`（2 项）与 `TvInteractionTest#libraryHeaderCanMoveDownAndEscapeReturnsToParent`
全部通过（`Finished 3 tests ... BUILD SUCCESSFUL`）。

## 验收第十七轮修订（用户提供录屏）

用户录了一段 7.3s 的电视端操作视频（1728×1080，29.98fps）。我用 OpenCV 按 0.4s 抽帧（20 帧，另存了全分辨率关键帧），
从帧序列确认：按下「下」后页面确实滚动了，但停在半途——工具行留在屏幕中部，**上方还露着一条 banner 的轮播条**
（约一个顶栏内边距的高度），随后稳定在该位置。也就是说上一轮"对齐到顶部后再回退 `pinnedTop`"这句是多余的，
正是它把 banner 的一条留在最上面。

修订：

1. `enterTools()` 只做一次 `animateScrollToItem(1)`，把工具行**整行对齐到视口顶端**（与首页"上/下区域切换"一致），
   去掉回退步骤。
2. 工具行自身带上 `padding(top = pageTopPadding)`：对齐到顶端后，标题与功能按钮正好落在顶栏下方，
   上方不再露出 banner 内容（背后是页面固定的 backdrop）。
3. 给该用例补了位置断言（工具行必须落在屏幕顶部区域），并把测试数据从 6 条改成 30 条——数据太短时页面根本
   滚不动，无法对齐，那是数据规模问题而非布局问题。

模拟器验证：`TvInteractionTest#libraryHeaderCanMoveDownAndEscapeReturnsToParent`（含新的位置断言）通过。

## 验收第十八轮修订（两个区域必须整屏切换）

用户要求：banner 区与媒体区在视觉上必须**二选一完整显示**，不能停在中间；媒体库按下后是
"纪录片 · 全部内容 + 右侧按钮"这一整行贴顶、banner 完全消失；首页同理，只是用"我的媒体库"替代工具行。

修订（最终实现）：

1. **媒体库**：`enterTools()` 先 `animateScrollToItem(1)`，聚焦工具行的排序按钮，**最后**再做一次位置纠正
   （正数位移把整行顶到最上面）。关键发现：LazyGrid 会把首个可见项画在自己的 `contentPadding` 下方，而
   `visibleItemsInfo.offset` 只报内容内偏移，所以之前"看起来对齐了、实际还差一个内边距"；纠正量必须是
   `contentPadding + 上报偏移`，符号为正。工具行本身带 `padding(top = pageTopPadding)` 让标题/按钮避开顶栏，
   但**不再铺任何底色**——上一版的"白方块"就是这层不透明背景造成的。
2. **首页**：向上聚焦"我的媒体库"时只调用 `revealLibraries()` 做整页吸附。上一版我在后面又加了一句
   `list.revealItem(0, …)`，而在触摸布局里索引 0 就是 banner 本身——于是"聚焦我的媒体库却把 banner 滚了回来"，
   随后上下键自然错乱。已删除该句。
3. 数据量太少的媒体库（内容总高不足一屏）无法滚动对齐，属于数据规模问题，不是布局问题。

4. **文件夹展开模式同样处理**：`moveFolder` 的落位原来用的是 `pinnedTop + toolsHeightPx`（钉住工具栏时代的写法），
   所以文件夹行会被放在工具行下方、上面留出 banner 边缘。现改为统一落在顶栏下方（`pinnedTop`）——文件夹标题、
   文件夹展开的媒体行、以及"更多文件夹"按钮都按这套落位，上下切换同样不会露出 banner。

5. 该页的 `StableVerticalViewport` 改为 `topInsetOverride = 0.dp`（原先的 76dp 内边距会把获得焦点的行重新推回顶栏下方），
   `gridFocus.topInset` 也改为 0，使媒体区内的落位规则一致。

**模拟器验证**：`TvInteractionTest#libraryHeaderCanMoveDownAndEscapeReturnsToParent` 通过（含"工具行必须落在屏幕
顶部区域"的位置断言）；并从用例里导出截图确认：banner 完全不可见、工具行紧贴顶栏下方、没有色块。

模拟器验证：`TvInteractionTest#libraryHeaderCanMoveDownAndEscapeReturnsToParent`（含"工具行必须落在屏幕顶部
区域"的位置断言）通过。
